# Обучение прогноза спроса (этап 8)

Пакет `sppr_ml` обучает двухэтапную LightGBM из текста ВКР, сравнивает её с
базовыми оценками и экспортирует каталог модели, который загружает Go-предиктор
SPPR (bootstrap через `PLANNER_MODEL_DIR`, затем реестр этапа 9). ТЗ — [docs/ml-spec.md](../../../docs/ml-spec.md).

## Быстрый старт

Из корня репозитория:

```bash
make ml-sppr-venv          # .venv с версиями из requirements.txt
make ml-sppr-train-all     # 6 синтетических сценариев (1000 объектов) → build/ml-models
make ml-sppr-report        # таблица метрик и разность с лучшей базовой оценкой
make ml-sppr-notebook      # пересобрать и выполнить notebooks/stage8.ipynb
make ml-sppr-traces        # наборы по трассам → build/ml-traces (входы — см. ниже)
make test-sppr-ml
```

Одна модель: `make ml-sppr-train SPPR_ML_DATA=<каталог cmd/dataset> SPPR_ML_OUT=<новый каталог>`.
Переобучение без перебора сетки, с выбранными ранее гиперпараметрами:
`python -m sppr_ml train --data … --out … --params '{"num_leaves": 15, …}'`.

`make ml-sppr-traces` ищет архивы IBM в `SPPR_TRACE_DOWNLOADS` (по умолчанию
`~/home/98_Downloads`) и неделю Meta CDN в `SPPR_META_TRACE`; где их взять —
[docs/traces.md](../../../docs/traces.md). Доля ключей, шаг среза и периоды каждой
трассы зафиксированы в `scripts/trace_datasets.py` до обучения.
Подключение к пустому реестру SPPR: `PLANNER_MODEL_DIR=<каталог модели>`.
Горизонт берётся из manifest набора и переносится в модель (не константа 3600);
частотная базовая оценка пересчитывается на тот же горизонт. Stage 9 передаёт
`--params` без сетки и держит test пустым; модель без регрессора не активируется.
Runbook реестра, таймаута и расписания — [README SPPR](../README.md#выбор-предиктора-и-каталог-модели).

## Что внутри

| Модуль | Назначение |
|---|---|
| `data.py` | срезы `slices.jsonl` или `<split>.csv.gz` → столбцы numpy; кеш — сырой файл на столбец, читается сразу в итоговый массив; прореживание train; test закрыт без явного флага |
| `model.py` | классификатор `binary` и регрессор `poisson` на `N − 1`; ранняя остановка по последним 8 ч train, затем обучение на всём train |
| `baselines.py` | EWMA, частота, возраст и давность (монотонная функция, подобранная на train) |
| `experiment.py` | обработка завершённой матрицы размещения: парные seed, 10 000 bootstrap, критерий, Markdown/JSON |
| `metrics.py` | PR-AUC, Brier, `Cov_K`, пуассоновское отклонение, bootstrap по моментам среза |
| `evaluate.py` | сетка гиперпараметров на validation, сравнение, парная разность с лучшей базовой оценкой, проверка на ещё не читанные объекты |
| `trace_test.py` | этап 11: воспроизведение выбора этапа 8, TEST всех базовых оценок и таблица по трассам |
| `final_evaluation.py` | этап 11: фиксированный train-only fit, TEST-метрики ML/EWMA и среднее/min–max по seed |
| `export.py` | `classifier.txt`, `regressor.txt`, `manifest.json`, `parity.json` по «Схеме файлов экспорта v1» |
| `scripts/build_notebook.py` | исходник notebook; правьте его, а не `.ipynb` |

## Правила честной проверки

- Гиперпараметры выбираются по validation (`Cov_K`, при равенстве Brier); число
  деревьев — по хвосту train. Validation не участвует в обучении деревьев.
- Монотонные отображения базовых оценок подбираются на train.
- В этапе 8 test не загружается: `data.load` без `include_test=True` его отбрасывает.
- `Cov_K` — отношение сумм по всем моментам среза; равные прогнозы упорядочиваются
  случайно с фиксированным seed, чтобы базовая оценка с массой нулей не выигрывала
  от порядка строк.

## Результаты на рабочей выборке

Шесть сценариев, seed 0, 1000 объектов по 1 МиБ, 2 чтения/с, срез раз в 15 мин
(`examples/data/medium.json`; на объект столько же чтений, сколько в профиле
приёмки). Разность `Cov_K` модели и лучшей базовой оценки на validation, 95 %
интервал парного bootstrap:

| Сценарий | Лучшая базовая | Разность | 95 % ДИ | Вывод |
|---|---|---|---|---|
| shift | EWMA | +0,028 | +0,005…+0,059 | модель лучше |
| stable | частота | +0,001 | −0,000…+0,002 | не доказано |
| burst | частота | −0,000 | −0,001…+0,001 | не доказано |
| uniform | частота | −0,000 | −0,001…+0,001 | не доказано |
| periodic | частота | −0,001 | −0,001…−0,000 | хуже |
| decay | частота | −0,002 | −0,003…−0,002 | хуже |

Модель выигрывает при резкой смене популярного набора; при постоянном или плавно
меняющемся спросе суточная частота не хуже. В `burst` всплеск приходится на
test-период, поэтому на validation сценарий равномерный. При ~7 чтениях в час на
объект нулевых меток почти нет в decay, burst и uniform — там PR-AUC и Brier
вырождаются. Обучение одного сценария с подбором по сетке (24 варианта) — до
2,7 мин и 490 МиБ. Профиль приёмки (10 000 объектов) и реальные трассы — часть 4.

## Обработка эксперимента размещения (этап 10a)

```bash
make sim-smoke
make experiment-report EXPERIMENT_OUT=build/sim-smoke
# Или напрямую из корня:
PYTHONPATH=services/sppr/ml services/sppr/ml/.venv/bin/python -m sppr_ml experiment build/sim-smoke
```

Обработка проверяет полную матрицу, конфиги, git SHA, хеши checkpoint/результатов,
затем для каждой базовой политики считает парное относительное уменьшение
среднего и 95 % ДИ (10 000 повторов по seed). Для p95 используется среднее
парных относительных изменений. Таблицы имеют строки «сценарий × бюджет»;
критерий проверяется против всех четырёх baseline. Чтения отдельно не bootstrap-ятся.
Выход — `experiment-report.json` и `experiment-report.md` внутри серии.

Симулятор вызывает `train --params '<JSON>' --fit-only`. Этот режим требует
фиксированные параметры, использует существующий `model.fit` с ранней остановкой
на train-tail и `export.write` схемы v1, пропускает подбор/сравнение validation.
Начальное обучение — первые 48 ч; обновления каждые 24 ч используют последние
48 ч и только полностью доступные часовые метки. Временная граница записана в
отдельном dataset manifest каждого обучения. Файлы с будущим test при этом
не создаются как вход обучения. Отказ экспортировать модель без повторных
чтений сохраняется. Время всего Python-процесса и последующей проверки Go
измеряется; новая модель включается после этой длительности в логическом времени.
Полный [runbook](../README.md#эксперимент-по-логическому-времени-этап-10a).

`SPPR_ML_PY` переопределяет Python для make (включая `make test-sppr-ml`), например
`make test-sppr-ml SPPR_ML_PY=build/experiment-venv/bin/python`.

## Итоговое качество прогноза (этап 11)

`make forecast-quality` из корня создаёт и удаляет по одному временному dataset
на seed, оставляя только `evaluate.json`. Параметры по умолчанию берутся из
`experiments/main.json` (simulation.params), без подбора на TEST. Отдельные CLI:

```bash
python -m sppr_ml evaluate --data <dataset-dir> --params '<fixed-json>' --out <new-dir>
python -m sppr_ml evaluate-report <seed-dir> <seed-dir> ...
```

Обучение использует `model.fit` как `train --fit-only`, train раз в 15 мин;
TEST читается после fit, validation не участвует. Метрики: PR-AUC (average
precision), Brier, MAE в чтениях на объект в час, Cov_K с HOT_SHARE=0.0921,
число строк. EWMA p=1−exp(−λ), λ — ожидаемые чтения за горизонт из dataset.
Результаты не экспортируются как модель. Подробности, параметры Make и границы
измерений — [runbook этапа 11](../README.md#измерения-для-вкр-этап-11).

### TEST моделей трасс после выбора этапа 8

```bash
# Полный прогон всех трасс; тяжёлая команда, нужна локальная копия исходников:
make ml-sppr-traces-test SPPR_TRACE_DOWNLOADS=<IBM-dir> SPPR_META_TRACE=<Meta-file>
# Одна трасса или сохранение dataset (из корня репозитория):
services/sppr/ml/.venv/bin/python services/sppr/ml/scripts/trace_test.py \
  --downloads <IBM-dir> --meta <Meta-file> --only meta-eag --keep-datasets
# Уже подготовленный dataset:
PYTHONPATH=services/sppr/ml services/sppr/ml/.venv/bin/python -m sppr_ml test-eval \
  --data build/ml-traces/datasets/meta-eag --out build/ml-traces/test/meta-eag
PYTHONPATH=services/sppr/ml services/sppr/ml/.venv/bin/python -m sppr_ml test-eval-report \
  build/ml-traces/test/meta-eag
```

`test-eval` воспроизводит `train`: train раз в 900 с (`--train-every`), полная
сетка этапа 8, выбор по validation с прежним правилом равенства и early stopping
на train-tail. `--params '<JSON>'` заменяет сетку одним фиксированным кандидатом,
как у `train --params`. После выбора и подбора базовых оценок на train матрицы
train/validation освобождаются; TEST загружается отдельно и не прореживается.
Для трасс используйте компактные split-файлы: JSONL — единый файл, загрузчик
читает его целиком, хотя возвращает только запрошенные splits.

Новый каталог содержит только `test-report.json` (`trace-test-v1`): выбранные
параметры, rounds и trials, manifest/происхождение/хеш данных/версии, TEST labels,
метрики всех методов с ДИ Cov_K, парные разности с каждой базовой оценкой,
проверку `never_read`, Brier и MAE в чтениях/объект/час для модели и EWMA
(p=1−exp(−λ)). Лучшая базовая **выбирается по TEST Cov_K**: это консервативное
сравнение, не выбор модели. Интервалы — 95 %, 1000 парных bootstrap по моментам
среза, seed 0; они не учитывают множественность сравнений. «Без never-read»
повторяет этап 8: обнуляет прогнозы всех методов на этих строках, сохраняя
каталог, K и метки, затем заново выбирает лучшую базовую. Колонка objects —
число версий каталога из source manifest; `test_objects` отдельно считает
версии с eligible TEST-строками. Без счётчика каталога таблица показывает «—».
Вердикт: нижняя граница ДИ >0 — «лучше», верхняя <0 — «хуже», иначе «не доказано».
IBM COS 001 всегда «не засчитано (утечка каталога)».

Скрипт повторно использует `trace_datasets.build` и прежние доли ключей/периоды.
Результаты — `build/ml-traces/test/<name>`; существующий каталог пропускается
(отсутствие `test-report.json` в нём — ошибка). После успеха dataset вместе с
кешами удаляется, если не задан `--keep-datasets`; конвертированные traces
сохраняются. При ошибке dataset остаётся для повторного запуска. Отчёт
публикуется целиком после оценки. Повторная таблица не открывает TEST.
Результаты validation в `docs/ml-report.md` эта команда не меняет.
