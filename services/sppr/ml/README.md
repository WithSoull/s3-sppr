# Обучение прогноза спроса (этап 8)

Пакет `sppr_ml` обучает двухэтапную LightGBM из текста ВКР, сравнивает её с
базовыми оценками и экспортирует каталог модели, который загружает Go-предиктор
SPPR (bootstrap через `PLANNER_MODEL_DIR`, затем реестр этапа 9). ТЗ — [docs/ml-spec.md](../../../docs/ml-spec.md).

## Быстрый старт

Из корня репозитория:

```bash
make ml-sppr-venv          # .venv с версиями из requirements.txt
make ml-sppr-train-all     # 6 синтетических сценариев (1000 объектов) → build/ml-models
make ml-sppr-report        # таблица метрик и разность с лучшей базовой оценкой
make ml-sppr-notebook      # пересобрать и выполнить notebooks/stage8.ipynb
make ml-sppr-traces        # наборы по трассам → build/ml-traces (входы — см. ниже)
make test-sppr-ml
```

Одна модель: `make ml-sppr-train SPPR_ML_DATA=<каталог cmd/dataset> SPPR_ML_OUT=<новый каталог>`.
Переобучение без перебора сетки, с выбранными ранее гиперпараметрами:
`python -m sppr_ml train --data … --out … --params '{"num_leaves": 15, …}'`.

`make ml-sppr-traces` ищет архивы IBM в `SPPR_TRACE_DOWNLOADS` (по умолчанию
`~/home/98_Downloads`) и неделю Meta CDN в `SPPR_META_TRACE`; где их взять —
[docs/traces.md](../../../docs/traces.md). Доля ключей, шаг среза и периоды каждой
трассы зафиксированы в `scripts/trace_datasets.py` до обучения.
Подключение к пустому реестру SPPR: `PLANNER_MODEL_DIR=<каталог модели>`.
Горизонт берётся из manifest набора и переносится в модель (не константа 3600);
частотная базовая оценка пересчитывается на тот же горизонт. Stage 9 передаёт
`--params` без сетки и держит test пустым; модель без регрессора не активируется.
Runbook реестра, таймаута и расписания — [README SPPR](../README.md#выбор-предиктора-и-каталог-модели).

## Что внутри

| Модуль | Назначение |
|---|---|
| `data.py` | срезы `slices.jsonl` или `<split>.csv.gz` → столбцы numpy; кеш — сырой файл на столбец, читается сразу в итоговый массив; прореживание train; test закрыт без явного флага |
| `model.py` | классификатор `binary` и регрессор `poisson` на `N − 1`; ранняя остановка по последним 8 ч train, затем обучение на всём train |
| `baselines.py` | EWMA, частота, возраст и давность (монотонная функция, подобранная на train) |
| `metrics.py` | PR-AUC, Brier, `Cov_K`, пуассоновское отклонение, bootstrap по моментам среза |
| `evaluate.py` | сетка гиперпараметров на validation, сравнение, парная разность с лучшей базовой оценкой, проверка на ещё не читанные объекты |
| `export.py` | `classifier.txt`, `regressor.txt`, `manifest.json`, `parity.json` по «Схеме файлов экспорта v1» |
| `scripts/build_notebook.py` | исходник notebook; правьте его, а не `.ipynb` |

## Правила честной проверки

- Гиперпараметры выбираются по validation (`Cov_K`, при равенстве Brier); число
  деревьев — по хвосту train. Validation не участвует в обучении деревьев.
- Монотонные отображения базовых оценок подбираются на train.
- Test не загружается: `data.load` без `include_test=True` его отбрасывает.
- `Cov_K` — отношение сумм по всем моментам среза; равные прогнозы упорядочиваются
  случайно с фиксированным seed, чтобы базовая оценка с массой нулей не выигрывала
  от порядка строк.

## Результаты на рабочей выборке

Шесть сценариев, seed 0, 1000 объектов по 1 МиБ, 2 чтения/с, срез раз в 15 мин
(`examples/data/medium.json`; на объект столько же чтений, сколько в профиле
приёмки). Разность `Cov_K` модели и лучшей базовой оценки на validation, 95 %
интервал парного bootstrap:

| Сценарий | Лучшая базовая | Разность | 95 % ДИ | Вывод |
|---|---|---|---|---|
| shift | EWMA | +0,028 | +0,005…+0,059 | модель лучше |
| stable | частота | +0,001 | −0,000…+0,002 | не доказано |
| burst | частота | −0,000 | −0,001…+0,001 | не доказано |
| uniform | частота | −0,000 | −0,001…+0,001 | не доказано |
| periodic | частота | −0,001 | −0,001…−0,000 | хуже |
| decay | частота | −0,002 | −0,003…−0,002 | хуже |

Модель выигрывает при резкой смене популярного набора; при постоянном или плавно
меняющемся спросе суточная частота не хуже. В `burst` всплеск приходится на
test-период, поэтому на validation сценарий равномерный. При ~7 чтениях в час на
объект нулевых меток почти нет в decay, burst и uniform — там PR-AUC и Brier
вырождаются. Обучение одного сценария с подбором по сетке (24 варианта) — до
2,7 мин и 490 МиБ. Профиль приёмки (10 000 объектов) и реальные трассы — часть 4.
